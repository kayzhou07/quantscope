# QuantScope 统一源码仓库设计

本次按已确认商业计划书执行资料与源码整合，不改变经营定位。公司量见 QuantScope；量寰 QuantVela 为研究项目，量曜 QuantOrion、量衡 QuantLibra、量枢 QuantPyxis 为三个模型。

## 架构与交付

采用单仓库：src/quantscope 下放 data、models、portfolio、adapters、interfaces。models 内四个独立子包使用同一信号契约。输入必须是已完成日期的数据；输出明确 signal_date、execute_after、version、status、risk_state、targets、reason。缺数据、失效、空仓分开。标准库核心可离线运行，不拉行情、不调大模型、不下单。

量寰按材料实现日线三态和月度波动率配置的独立规则函数，标明本次新增规则实现，不冒充历史回测源码。量曜保留连续两日涨停与缩量基线，0.7变体另存。量衡保留25/26观察值版本差异，以原有本地信号26点作为统一默认，不偷偷更改；冷却按自然日。量枢以冻结A评分和仓位预算为基准，保留冻结状态截止日及原始平台实现，统一核心只计算目标快照，不冒充完整撮合复现。

组合层只合并三个模型的同日同执行日期目标，显式配置预算；量寰不纳入自有资金演示。输入失败、不同日期、负权重、预算超限立即拒绝。目标仓位与实际成交分离，预留按行业归类的集中度检查及现金。SuperMind 为目标导出适配器，保持离线、无交易凭据；量枢历史平台脚本可独立查看，量曜/量衡未声称平台原生迁移完成。

旧项目保留为 prototypes/quantorion、prototypes/quantlibra 及 research/quantpyxis/platform 与 legacy；品牌替换有迁移表和原始哈希。历史多版本、依赖和平台路径独立，禁止并入核心默认导入。资料、输出和历史行情区分，精简研究说明随仓库提供；全量素材、数据及证据另作本地归档并提供索引。运行缓存、真实持仓、虚拟环境、个人数据、密钥、绝对用户路径不进入发布包。默认专有版权声明，不替用户作开源授权。

## 验收

先编写规则及边界测试，验证初始失败，再实现核心。比较量衡与旧纯函数、量曜阈值边界、量枢百分位与冻结截止、量寰三态及杠杆插值。测试重复资产、日期不一致、失败状态、研究项目入组合、现金和单资产/行业上限。统一CLI读取JSON、输出JSON；HTTP只监听回环，提供模型清单和同一信号入口。仓库有README、参数说明、架构、迁移、数据契约、快速开始、CI、环境变量示例、Git忽略、发布检查。新核心、旧源码静态检查分开报告。最终ZIP完整性、敏感扫描、安装与离线例子可复现。
